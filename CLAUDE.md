## Build and test commands

Run from `android-app/` (Git Bash: `./gradlew`, PowerShell: `.\gradlew.bat`). Requires JDK 17+ (`JAVA_HOME`, currently JDK 21) and the Android SDK (`local.properties` with `sdk.dir`, git-ignored; use forward slashes in the path).

- Build debug APK: `./gradlew assembleDebug`
- Unit tests (JVM): `./gradlew test`
- One unit test: `./gradlew test --tests "cz.talkative.app.ui.client.ClientViewModelTest"` (or `...ClientViewModelTest.initialState_hasNoProfile`)
- Instrumented/Compose tests (need a running emulator or device): `./gradlew connectedAndroidTest`. Run the classes one at a time (a whole-package run has crashed the emulator or hit low memory); with a phone attached too, set `ANDROID_SERIAL=emulator-5554`. `SentencePlaybackTest` (1 s MP3 fixture) and `AdminFlowTest` are occasionally flaky.
- One instrumented test class: `./gradlew connectedAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=cz.talkative.app.ui.NavigationTest`
- Install and launch: `./gradlew installDebug`, then `adb shell am start -n cz.talkative.app/.MainActivity`
- Headless emulator: `%LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe -avd Medium_Phone_API_37.0 -no-window -no-audio`; stop it with `adb emu kill`.

Toolchain notes: AGP 9.4.1 needs Gradle 9.6.0 (wrapper) and has built-in Kotlin (no `kotlin-android` plugin); versions are in `gradle/libs.versions.toml`. Compose UI tests use `androidx.compose.ui.test.junit4.v2.createComposeRule` and Espresso 3.7.0 (older Espresso crashes on API 37). Room schemas are exported to `app/schemas/`. Compose UI tests run against stateless screens (`TalkativeNavHost` takes the screens as parameters), so they do not need Hilt.

Package layout (`cz.talkative.app`): `ui/` (theme, `common`, `client`, `admin`, `config`, `exchange`, `about`, `notice`, `arasaac`, `draw`, `navigation`, `preview`; MVI-style `UiState`/`Event` + `ViewModel`; `preview/ScreenPreviews.kt` holds the Android Studio `@Preview`s of the stateless screens), `domain/` (model, repository interfaces, use cases), `data/` (Room `local/`, repository implementations), `di/` (Hilt modules). Custom sounds (MP3 or M4A) live in `filesDir/audio` via `AudioStore` (max 60 s / 5 MB, format detected by `MediaMetadataRetriever`, checked on a temp copy); `AudioPlayer.play` is a suspend function that returns when the clip ends and releases the player on cancel. Images are stored resized (max 512 px) in `filesDir/images` via `ImageStore`, shown with Coil through `LocalImageResolver`; orphan image files and `cache/camera` are cleaned at app start. Instrumented dialog tests use `NoSoftKeyboardRule` (androidTest only) because the soft keyboard resizes dialogs. Fakes shared by JVM and instrumented tests live in `src/sharedTest/java` (e.g. `FakeSpeechProvider`). `SpeechProvider` is deliberately not a singleton: `ClientViewModel` owns an instance and shuts it down in `onCleared`. Sizes/colors/typography come from `ui/theme` (`TalkativeTheme.dimens`, `MaterialTheme`); strings are in `res/values/strings.xml` (Czech).

## Product summary

Android AAC-style (communication aid) app "Talkative": the user assembles a sentence from predefined words and the app reads it aloud via TTS. Same app and same device for both roles; the app always starts in **client mode**, and the admin UI is entered by long-pressing (default 10 s) a hidden control. There is no PIN — it only guards against accidental entry.

- **Data model**: folders (nested arbitrarily) and words. Both have a title; words also have an optional image and an optional alternate audio (different TTS text, or a custom sound: MP3/M4A file or a microphone recording). Each word has its own ID, titles need not be unique, words belong to exactly one folder and are never copied. Items are manually ordered by the admin (quick alphabetical sort uses a configurable collation). Store the dictionary under a `default` profile so multiple profiles can be added later without a model rewrite.
- **Client UI**: sentence bar at the top, paged grid of folders/words below, breadcrumbs plus large Back/Home buttons. Add words by tap or drag (configurable), remove by long-press or dragging off the bar, reorder by dragging within the bar (can be disabled). The in-progress sentence is not persisted across restarts.
- **Playback**: sequential; adjacent TTS words are merged into one utterance, an MP3 word interrupts TTS and then playback continues. Play button turns into Stop while playing. TTS and MP3 playback sit behind a common interface (e.g. `SpeechProvider`) so more voice providers can be added.
- **Admin**: CRUD for words/folders, multi-select move, ordering, export/import, per-device configuration. Deleting a non-empty folder is recursive with a confirmation showing the item count; there is no trash.
- **Configuration is local to each device and is NOT synced** (grid size, tap/drag mode, add/remove/admin-entry hold intervals, play-on-tap, collation, hide captions in sentence, auto-clear after playback, text size). Defaults are listed in `assignment.md`.

## Architecture decisions

- Native Android, **Kotlin** (Java was considered and rejected because Compose is Kotlin-only), Jetpack Compose, Material 3, minSdk 26 (Android 8.0). If a library needs a newer minSdk, stop and ask. Write simple, readable Kotlin — the owner knows Java.
- MVVM/MVI with clear UI / domain / data layers, Hilt, Coroutines + Flow. Priority is a clear, easy-to-follow architecture.
- Room for local storage; the folder tree is an adjacency list (each folder/word stores its parent folder ID, root has none). All sizes, fonts, and colors come from the theme.
- applicationId `cz.talkative.app` (can be changed later, but gets harder once Google sign-in/publishing exists). Target device is a generic Android tablet; support portrait and landscape.
- **Offline-first**: local storage (Room + files) is the source of truth; the app must work fully offline. Google Drive (hidden `drive.appdata` folder) stores everything (JSON metadata plus image/MP3 files) so a new device pulls the same data for the same account. Account is chosen via the system dialog on first run; until then the app is local-only.
- **Sync**: automatic after each admin change (when online), on app start, and via a manual button; retry later on network failure. Last-write-wins. Deletions are kept as timestamped tombstones; delete-vs-edit conflicts are won by the newer change. The app must tolerate multiple installs writing to the same Drive and recover from inconsistency rather than guarantee consistency. A warning mark (exclamation icon) on a word signals: missing image/MP3 file, reference to a nonexistent folder, or an unresolvable sync conflict.
- **Export/import**: ZIP with `manifest.json` (schema version) plus media directories, via the Storage Access Framework. Export contains folders, words, and media; configuration is an optional checkbox. Import only adds (new IDs), never overwrites, with an optional replace-all; partial import goes into a user-chosen target folder (default root).
- Image handling: images are downscaled when saved (e.g. 512 px); custom sounds are limited to tens of seconds (60 s / 5 MB). Image sources are the device gallery, camera, ARASAAC pictograms and a finger drawing.
- Accessibility: touch targets of at least 64 dp, high contrast, no complex gestures, no time-limited actions.
- Distribution is internal (APK / internal testing) for now. Tests should be written so they actually verify the required behavior: unit tests for domain and repositories, Compose UI tests for key client scenarios.
- Data stays on the device and in the user's private Drive; no custom servers.
